

## homevisit-app（地域見守り支援員 家庭訪問管理アプリ）

「必要な情報を、その場ですぐに確認できること」を重視し、現場の支援員向けに開発した家庭訪問管理アプリです。<br>
家庭訪問時に膨大な紙資料をめくる負担を減らし、対象者の「過去の訪問経緯」や「現在の状況」をその場ですぐ確認できるよう設計しました。

## こだわった工夫と技術的解決（UI/UX・設計）

システム全体を通して、「現場のユーザー視点に立ち、いかに面倒な手入力を減らしてストレスを軽減できるか」を追求しました。

### 1. Gemini 2.5 Flashを活用した音声入力＆日時自動入力UI
- **<課題>** ターゲットユーザーはシニア層を想定しており、<br>訪問直後にスマートフォンから毎回文字入力を行うのは現場の大きな負担となると考えました。

- **<解決>** 音声だけで訪問履歴を入力できる機能を実装し、さらにJavaScriptを用いて、<br>**文字起こし完了と同時に「現在のシステム日時」を訪問日欄へ自動マッピングする仕組み**を構築し、入力の負担を大幅に軽減しました。


### 2. API制限と運用コストを意識した「オンデマンドAI要約」への改善
- **<課題>** 当初は画面遷移時に自動で「過去履歴のAI要約」を走らせていましたが、<br>ユーザーの操作（マイクテストやリロードなど）だけでAPIの利用上限に達してしまう課題を発見しました。
  
- **<解決>** 画面ロード時の自動通信を廃止し、**緑色の「訪問履歴AI要約」ボタンを押した時だけ通信が走る「オンデマンド実行」へリファクタリング**を行いました。
  <br>これにより、不要なAPI通信を防ぎ、運用コストを抑えられる構成へ改善しました。


### 3. 直感的な「あかさたな（頭文字）」検索機能
- **<課題>** 高齢の支援員や、文字入力が苦手なユーザーにとって、<br>毎回キーワードをタイピングして検索するのは心理的にもハードルが高いという懸念がありました。
  
- **<解決>** 1クリックで瞬時に顧客を絞り込める「頭文字検索ボタン」を設置しました。<br>キーワード検索と組み合わせてもスムーズに利用できるように実装しました。

## 画面構成

## テスト・品質

品質と安全性の担保のため、PHPUnitによる自動テストを導入しています。<br>
正常系だけでなく、現場でのバグや不正アクセスを防ぐための**異常系テスト**を特に重点的に実装しています。

- **認証セキュリティ:** 未承認状態（401 Unauthorized）でのアクセスブロックの検証
- **堅牢性:** 存在しない顧客ID（404 Not Found）を指定された際のハンドリング検証
- **バリデーション:** 入力エラー（422 Unprocessable Entity）時の適切なメッセージ返却検証
- **セキュリティ指摘への対応:** SQLインジェクション、XSS、CSRF対策、および複数回ログイン失敗時の自動アカウントロック機能実装
